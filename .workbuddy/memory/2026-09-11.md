## 打包脚本修复（build_exe.ps1）

- 根因A（用户报的 `Script file 'main.py' does not exist`）：原脚本在 `scripts/` 目录被启动，
  PowerShell 工作目录非项目根，相对路径 `main.py` 解析失败。
- 根因B（用户随后报的 parse 报错）：`.ps1` 以 UTF-8 **无 BOM** 写入；在中文 GBK 代码页(936)
  下 PowerShell 5.1 把 UTF-8 中文按 GBK 解码，多字节序列吞掉紧随的 `"` →
  `字符串缺少终止符` / `UnexpectedToken`。沙箱(英文1252)下反而"侥幸"能解析。
- 根因C（沙箱侧）：本沙箱有 safe-delete 钩子，拦截 `Remove-Item`（`SAFE_DELETE_FAIL_CLOSED`，
  refusing fallback delete），抛出的异常连 `-ErrorAction SilentlyContinue` 都压不住，
  配合 `$ErrorActionPreference="Stop"` 直接终止脚本。用户本机无此钩子，属沙箱限制。
- 修复：脚本改用 `$PSScriptRoot` 上级（项目根）`Set-Location`；改用
  `pyinstaller PicCrawler.spec --noconfirm` 复用含 hiddenimports 的 spec（**不再删除 spec**）；
  cleanup 用 `try/catch` 包裹 `Remove-Item`（任何删除失败都不致命）；用 **UTF-8 BOM** 重写。
- 验证：写入后 BOM=`ef bb bf`、Parse OK；`.venv`(Py3.13.9) 实跑 `BUILD_EXIT=0`，
  `dist/PicCrawler.exe` 重新生成(30,277,180B)；启动后 `GET /` 与 `GET /api/rules` 均 200。
- 注意：重建时需把旧 `dist/PicCrawler.exe` 让位（沙箱禁删，用 rename 移开绕过）；
  用户本机正常 `Remove-Item` 即可。

## asmhentai「在线浏览没有主题」修复

- 现象：asmhentai 规则在线浏览主题列表为空（前端显示「当前页没有主题」）。
- 诊断：解析器本身正确（用样本 HTML 单元测试验证可解析出标题+封面）。根因在**网络层**——
  `crawler_asmhentai.py` 此前用裸 `requests.Session()`，而 asmhentai 站点在 Cloudflare 后面，
  裸请求拿到挑战页（无 `div.preview_item`）→ 解析返回空。
  兄弟站点（wnacg/hotgirl/xchina）都用 `cloudscraper` 兜底，asmhentai 漏了。
- 修复：给 asmhentai 加 `cloudscraper` 兜底（与兄弟站点一致）：
  - `import cloudscraper`（try/except 降级为 None，不可用时退化为裸请求）
  - `__init__` 构建 `_cf_session`；新增 `_build_cloudflare_session` / `_looks_like_challenge` /
    `_request_page` / `_warmup_cloudflare_session` / `_sync_cookies_from`
  - `_request_page` 依次试 cf 会话→裸请求，跳过挑战页/5xx；`list_topics`/`_fetch_detail`/
    `_topic_images_fallback` 的 `session.get` 全部改走 `_request_page`
- 验证：新增 `tests/test_asmhentai.py`（5 项：挑战页检测、cf 失败后回退真实 HTML、解析一致性、
  集成形态）；全量 46 pytest + 43 基线全 PASS。
- 说明：强烈推断是 Cloudflare 拦截。若用户实跑仍为空，需请其提供真实 HTTP 响应
  (status + 片段) 以区分「仍是 CF 拦截」还是「站点 HTML 结构漂移（选择器失效）」。
